# Soulrip 서비스 기획 프롬프트 아카이브

> 본 문서는 **서울 지역 공공데이터 기반 혼행 정보 서비스 `Soulrip`의
> 기획 과정에서 생성형 AI를 활용한 프롬프트 설계 및 의사결정 과정을
> 기록한 문서**입니다.\
> 개발 의뢰서(RFP) 분석을 시작으로 요구사항 우선순위화, 기능 평가, MVP
> 범위 정의, 개발 일정 수립, UI 방향 설정, 서비스 컨셉 구체화까지
> 단계별로 프롬프트를 고도화했습니다.

## 1. RFP 요구사항 구조화

### Prompt

``` text
20년 이상의 프로젝트 관리 경험을 가진 PM의 관점에서 첨부한 개발 의뢰서(RFP)를 분석해줘.

요구사항을 [구분(필수/선택/제약), 항목, 상세 내용, 근거 조항, 검토 의견]으로 구조화하여 표로 정리해줘.

특히 '반드시', '금지', '절대' 등 강제성을 나타내는 표현이 포함된 조항은 일반 요구사항과 분리하여 제약사항으로 명확하게 분류해줘.
```

### Prompt - MoSCoW 기반 우선순위 재구성

``` text
분석한 요구사항을 MoSCoW 우선순위 기법에 맞게 재구성해줘.

Must는 반드시 구현해야 하는 핵심 요구사항,
Should는 중요도가 높아 우선적으로 고려할 요구사항,
Could는 일정과 리소스에 여유가 있을 경우 구현할 요구사항,
Won't는 현재 개발 범위에서 제외할 요구사항으로 정의해줘.

기존 분석 내용을 유지하면서 각 요구사항의 우선순위가 명확하게 드러나도록 정리해줘.
```

## 2. 기능 후보 평가 및 구현 우선순위 선정

### Prompt

``` text
다음 프로젝트 제약조건을 고려하여 선택 기능 후보를 평가해줘.

- 개발 기간: 3일
- 개발 인원: 신입 개발자 중심의 3인 팀
- 기술 스택: Vue.js 3 + FastAPI + SQLite
- 개발 환경: VSCode Copilot + OpenAI API만 사용 가능

각 기능을 [구현 난이도 1~5, 실현 가능성 1~5, 사용자 임팩트 1~5] 기준으로 평가하고 표로 정리해줘.

구현 난이도는 낮을수록 개발 부담이 적은 것으로 평가하고,
실현 가능성은 현재 팀이 제한된 기간 내 안정적으로 구현할 가능성,
사용자 임팩트는 실제 서비스 이용 과정에서 사용자가 체감하는 가치와 효과를 기준으로 평가해줘.

평가 결과를 바탕으로 현재 프로젝트 조건에 적합한 기능을 추천하고 선정 근거를 설명해줘.
```

### Prompt - RFP 필수 기능 반영

``` text
기능 평가 범위에 RFP에서 필수로 지정한 익명 커뮤니티 CRUD와 지역 정보 챗봇이 누락되어 있어.

다음 필수 요구사항을 평가 대상에 포함하여 전체 기능 우선순위 표를 다시 구성해줘.

1. 익명 커뮤니티 CRUD
- 회원가입 및 로그인 없이 이용
- 게시글 목록, 상세, 작성, 수정, 삭제
- 수정용 비밀번호 기반 수정·삭제 권한 확인
- 커뮤니티 데이터 DB 저장

2. 지역 정보 챗봇
- FastAPI POST /api/chat 엔드포인트 구현
- 제공 JSON 기반 자연어 지역 정보 질의응답
- 관광지 추천, 축제 일정, 지역 정보, 커뮤니티 게시글 검색 등 주요 질의 대응
- 대화 히스토리 유지 및 모바일 대응 채팅 UI

필수 기능은 평가 점수와 관계없이 반드시 구현해야 하는 기능으로 명확하게 표시해줘.
```

## 3. MVP 범위 정의

### Prompt

``` text
앞서 분석한 RFP 요구사항과 기능 평가 결과를 기반으로 프로젝트의 MVP 범위를 MoSCoW 방식으로 정의해줘.

Must Have는 RFP에서 필수로 지정한 요구사항을 그대로 반영하고,
Should Have와 Could Have는 구현 난이도, 실현 가능성, 사용자 임팩트 평가 결과를 고려하여 구분해줘.

Won't Have에는 3일이라는 개발 기간과 3인 팀의 리소스를 고려했을 때 현재 MVP 범위에서 제외할 기능을 명확하게 정의해줘.

각 기능의 분류 근거와 검토 의견이 드러나도록 표 형태로 작성해줘.
```

### Prompt - 서비스 대상 및 문제 정의 구체화

``` text
MVP 정의서에 다음 서비스 기획 방향을 반영해줘.

- 선정 권역: 서울
- 핵심 문제: 혼자 서울을 여행하거나 서울을 처음 방문한 관광객은 다양한 지역 정보가 여러 데이터와 채널에 분산되어 있어, 자신의 상황과 취향에 맞는 장소 및 여행 정보를 탐색하는 데 어려움을 겪는다. 또한 실제 방문 경험을 공유하고 참고할 수 있는 통합 채널이 부족하다.
- 타깃 사용자: 서울 방문 관광객 및 지역 주민 중 회원가입 부담 없이 지역 정보를 탐색하고 경험을 공유하려는 익명 이용자

위 내용을 바탕으로 핵심 문제와 타깃 사용자가 서비스 기능과 자연스럽게 연결되도록 MVP 정의서를 수정해줘.
```

## 4. WBS 및 단기 개발 일정 수립

### Prompt

``` text
확정된 MVP 범위를 기반으로 3일 개발 프로젝트의 WBS를 작성해줘.

프로젝트 시작일은 2026-07-14이며 최종 납기는 2026-07-16이야.

대분류는 다음과 같이 구성해줘.
[기획, 설계, 개발, 배포, 테스트, 문서화, 발표준비]

각 작업은 [작업명, 담당자(FE/BE/팀전체), 시작일, 종료일, 선행작업] 항목으로 세분화하여 표로 작성해줘.

3인 팀이 Vue.js 3, FastAPI, SQLite를 활용하여 개발한다는 점을 고려하고,
프론트엔드와 백엔드 작업을 병렬로 진행할 수 있도록 현실적인 일정과 선행 관계를 설계해줘.
```

### Prompt - 기능 범위 변경 반영

``` text
'복수 관광지 및 장소 이동 경로 안내' 기능을 현재 MVP의 제외 범위가 아닌 Should/Could Have 기능으로 재분류했어.

변경된 우선순위를 반영하여 WBS의 개발 작업, 선행 관계, 테스트 범위를 수정해줘.
```

### Prompt - 간트차트 및 협업 문서 형식

``` text
작성한 WBS를 기반으로 2026-07-14부터 2026-07-16까지의 3일 개발 일정을 간트차트 형태로 시각화해줘.

기획, 설계, 개발, 배포, 테스트, 문서화, 발표준비 작업의 진행 기간이 날짜별로 명확하게 구분되도록 구성해줘.

또한 팀 협업 문서에 바로 활용할 수 있도록 Notion에 복사하여 붙여넣기 쉬운 표 형식으로 제공해줘.
```

## 6. 혼행 특화 서비스 컨셉 고도화

### Prompt - 차별화 아이디어 탐색

``` text
Soulrip에 혼자 여행하는 사용자를 위한 차별화 요소를 추가하고 싶어.

단순한 서울 관광 정보 제공을 넘어, 혼자 여행하는 사용자가 실제로 체감할 수 있는 기능이나 콘텐츠를 제안해줘.

예를 들어 혼자 방문하기 좋은 장소, 혼자 즐기기 좋은 여행 코스처럼 '혼행'이라는 사용자 상황을 중심으로 서비스의 차별화 포인트를 도출해줘.
```

### Prompt - 제공 데이터 기반 컨셉 재정의

``` text
Soulrip의 서비스 컨셉 자체를 '혼자 여행'에 더욱 집중하는 방향으로 재정의하고 싶어.

현재 제공받은 서울 지역 데이터는 다음과 같아.

- 관광지
- 레포츠
- 문화시설
- 쇼핑
- 숙박
- 여행코스
- 축제·공연·행사

모든 데이터는 JSON 형식으로 제공돼.

제공 데이터의 범위를 벗어난 기능을 억지로 추가하기보다, 기존 데이터를 혼행 사용자의 관점에서 재해석해 서비스 차별성을 만들고 싶어.

이 데이터를 활용하여 혼자 서울을 여행하는 사용자가 장소를 발견하고, 여행 계획을 세우고, 자신의 경험을 공유하는 서비스 컨셉을 제안해줘.

또한 RFP 필수 기능인 지역 정보 챗봇과 익명 커뮤니티가 서비스 컨셉 안에서 자연스럽게 연결되도록 핵심 사용자 흐름을 정의해줘.
```

## 8. 프롬프트 설계 원칙

기획 과정에서는 생성형 AI가 일반적인 아이디어를 제안하는 데 그치지
않도록 다음 정보를 프롬프트에 명시했습니다.

-   **역할 정의**: 20년차 PM 관점의 요구사항 분석
-   **프로젝트 일정**: 3일 단기 개발 프로젝트
-   **팀 리소스**: 신입 개발자 중심의 3인 팀
-   **기술 제약**: Vue.js 3 + FastAPI + SQLite
-   **AI 도구 정책**: VSCode Copilot + OpenAI API만 사용 가능
-   **서비스 권역**: 서울
-   **데이터 범위**: 관광지, 레포츠, 문화시설, 쇼핑, 숙박, 여행코스,
    축제·공연·행사
-   **핵심 사용자**: 혼자 서울을 여행하는 사용자
-   **출력 구조**: 요구사항 분석표, MoSCoW, 기능 평가표, MVP 정의서,
    WBS, 간트차트

초기 AI 응답에서 필수 기능이 누락되거나 서비스 범위가 제공 데이터와 맞지
않는 경우, 추가 제약조건과 프로젝트 맥락을 프롬프트에 반영하여 결과를
반복적으로 보정했습니다.

이를 통해 AI의 결과를 그대로 채택하기보다 **요구사항 분석 → 제약조건
반영 → 결과 검토 → 프롬프트 보완 → 기획 의사결정**의 반복적인 프로세스로
활용했습니다.
